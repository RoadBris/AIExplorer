# AIExplorer v0.10.0 검증 기록

## 검색 동작 계약

- 제목 검색의 새 파일명·확장자 후보는 오른쪽 목록뿐 아니라 통합 검색 결과에도 즉시 병합됩니다.
- `stl 파일`, `이미지 파일`, `폴더`처럼 파일명 키워드가 없는 구조화 질의는 확장자·종류·폴더 조건만으로 결과를 반환합니다.
- 빠른 제목 후보는 AI 분석 여부와 관계없이 보존되며, 본문·OCR·E5·SigLIP 근거가 추가되면 같은 항목의 순위와 배지가 갱신됩니다.
- 제목 검색이 직접 드라이브를 순회하는 동안 통합 검색은 같은 위치를 별도로 다시 순회하지 않습니다.
- 저장된 AI 벡터를 새 색인보다 먼저 검색하며, 사용자 검색 중 새 색인은 최대 4개의 제한된 단계만 실행합니다.
- 단일 용어는 E5 의미 후보를 사용할 수 있지만, 강한 파일명·본문 직접 일치가 있으면 관련 없는 독립 의미 후보를 숨깁니다.
- 본문이 없는 일반 사용자 파일도 파일명·상대 경로·유형으로 E5 의미 색인을 만들 수 있습니다.
- 이미지 검색은 여러 시각 문구의 동의를 사용하고, 캐릭터 고유명의 한글·영문 음역을 파일명과 상위 폴더명에서 함께 확인합니다.

## 이 환경에서 실행한 검사

- XAML XML 구문, 이벤트 처리기, 정적 리소스 참조 검사
- C# 주석·문자열 제거 후 괄호·범위·보조 메서드 계약 검사
- 검색 정책, 점진 검색, 숨김·임시 파일 제외, AI 번들, PowerShell·CMD 구조 검사
- C# 전체 소스 Tree-sitter 구문 분석
- 배포 소스 ZIP 무결성 및 생성물 제외 검사

## Windows에서 추가로 실행할 검사

현재 검증 환경에는 .NET 10 Windows WPF SDK가 없어 실제 WPF 컴파일과 Windows OCR·DirectML·SMB 실행 검사는 수행할 수 없습니다. Windows 10/11의 프로젝트 루트에서 다음 순서로 확인합니다.

1. `verify_source.cmd`
2. `build_release.cmd`

`verify_source.cmd`는 Release 빌드와 검색 스모크 테스트를 실행하고, `build_release.cmd`는 self-contained 실행 파일과 로컬 AI 모델을 묶습니다.
