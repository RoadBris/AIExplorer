# v0.7.0 검색 엔진 업그레이드

## 변경 목적

v0.6.4의 검색은 OpenCLIP의 영어 중심 시각 공간과 Nomic 기반 문서 임베딩에
의존했습니다. v0.7.0은 실제 배포에서 "관련 파일을 최소한 후보로는 찾는 것"을
우선해 문서와 이미지를 서로 다른 전문 모델로 분리했습니다.

## 새 구조

- 텍스트·문서: Multilingual E5 Base Q4_K_M, 768차원
- 이미지·PDF 화면: SigLIP 2 Base Patch16 224 INT8, 768차원
- 시각 실행: ONNX Runtime DirectML 우선, 호환 실패 시 CPU 자동 폴백
- 토큰화: SigLIP 2의 SentencePiece 모델을 Microsoft.ML.Tokenizers로 로컬 처리

## 정밀 재평가 복구

이전 실행기의 `--ubatch-size 128`보다 긴 입력이 들어오면 137토큰 같은 문장도
실패했습니다. v0.7.0은 E5 서버를 `ctx 512 / batch 2048 / ubatch 512`로 실행하며,
입력을 최대 240자 대표 구간으로 나눠 한 요청에 최대 4개만 보냅니다. 긴 문서는
앞·중간·뒤 대표 구간을 각각 임베딩한 뒤 평균 정규화합니다. 서버가 토큰 한도를
다시 보고하더라도 요청을 한 문장씩 분리하고 더 짧게 줄여 재시도합니다.

## 색인 변경

- 의미 색인 형식 4, E5 전체 768차원 int8 저장
- 시각 색인 형식 3, SigLIP 2 전체 768차원 int8 저장
- 자동 준비: 위치당 의미 192개, 시각 48개
- 활성 검색: 의미 신규 최대 384개, 시각 신규 최대 256개
- 시각 후보 비교 최대 300개
- 정밀 재평가 상위 30개에서 상위 50개로 확대
- E5 후보 문턱을 완화하고 후보 상한을 200개로 늘려 검색 누락을 줄임

모델 ID와 색인 형식이 바뀌므로 기존 Nomic·OpenCLIP 벡터는 사용하지 않고 새로
생성합니다. 개인 파일은 변경하지 않습니다.
