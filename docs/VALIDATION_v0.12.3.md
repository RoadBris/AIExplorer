# AIExplorer v0.12.3 검증 기록

## 실패 원인

v0.12.2는 의미 AI 결과가 약한 직접 본문 후보에 덮어쓰이지 않았는지 확인하면서
결과 설명에 `본문`이라는 문자열이 전혀 없는지를 검사했습니다. 새 의미 AI
안내문은 “검색어가 실제 본문에 있다는 뜻은 아닙니다”라는 부정문이었으므로,
검색 근거 종류와 배지는 정상이어도 문자열 검사만 실패했습니다.

## 수정 계약

- 결과 근거 종류가 `SearchEvidenceKind.SemanticCandidate`인지 확인합니다.
- 설명에 다음과 같은 직접 내용 근거가 붙었는지 별도로 확인합니다.
  - `파일 본문에서`
  - `본문 앞부분에서`
  - `엑셀 시트·셀에서`
  - `이미지 OCR에서`
  - `PDF 표본`
- 의미 AI 설명의 일반적인 단어나 부정문은 실패 조건으로 사용하지 않습니다.
- 의미 AI 설명은 `검색어를 파일에서 직접 확인했다는 뜻은 아닙니다`로 표시합니다.

## 사전 회귀 차단

교차 플랫폼 소스 검증과 Windows 사전 검사는 다음을 확인합니다.

- 의미 후보 테스트가 근거 열거형을 확인하는지
- 직접 내용 근거 판별 함수를 사용하는지
- `semanticOnlyResult.Reason.Contains("본문")` 형태의 취약한 검사가 없는지
- 의미 AI 안내문과 사전 검사 계약이 동일한지

## 이 환경에서 실행한 검사

- `python3 tools/validate_source.py`
- Tree-sitter C# 전체 파일 구문 분석
- XAML XML·이벤트·정적 리소스 검사
- 동일 범위 지역 변수 중복 및 경고 오류 승격 계약 검사
- PowerShell UTF-8 BOM 및 CMD CRLF 검사
- 소스 압축 무결성 및 빌드 출력 제외 검사

현재 Linux 작업 환경에는 .NET SDK가 없어 Windows WPF 빌드와 스모크 테스트를
실행할 수 없습니다. Windows에서는 `verify_source.cmd`가 Release 빌드와 전체
스모크 테스트를 통과해야 `build_release.cmd`가 배포본을 생성합니다.
